# 新建测评与运行记录 · 第一版功能规划

版本：v0.2（讨论稿）

日期：2026-10-29

状态：产品规划；四项关键决策已确认（见第 8 节），接口与持久化能力待核实；本文不代表功能已实现。

## 1. 产品定位与目标

平台以**测评任务和结果**为中心，面向内部研发和测试人员。用户需要阅读一次测试的问题与回答，但每天可能运行数百条测试，因此不把每次运行设计成独立聊天会话，也不建立聊天记录式侧栏。

第一版的主线是：**准备题目 → 创建单题测评 → 后台运行 → 查看回答与评分 → 从运行记录回看**。

建议导航：**题库 · 新建测评 · 运行记录**。登录后的默认首页建议为运行记录；任务详情由新建测评和运行记录共用。页面视觉遵循 `docs/产品界面设计规范.md`。

## 2. 第一版范围

### 包含

- 1110 单题测评。
- 直接输入题目，或从题库选择一道可用于 1110 的题目。
- 创建任务并查看运行状态、问题、回答、Markdown 机检及 DeepSeek / Qwen 独立评分。
- 运行记录列表、基础搜索筛选及详情入口，具体能力以确认后的后端接口契约为准。
- 已获得运行 ID 时，刷新或断线后查询原运行，不自动重新创建。
- 真实的加载、空结果、无权限和失败反馈。

### 暂不包含

- 多题批量执行、批次管理和失败重跑。
- 多服务或多版本横向对比。
- 测评报告导出、人工复核工作流。
- 连续多轮聊天、聊天记录侧栏、追问会话管理。

未来批量能力建议由一个批次包含多条单题运行，继续复用单次运行详情；具体模型与实现待后续设计。

## 3. 新建测评

### 3.1 页面目标与入口

页面采用表单式流程，帮助用户完成**选择服务、准备题目、确认发起**。不以聊天窗口作为新建入口。

- 在导航或运行记录页点击「新建测评」，进入新建页面。
- 从题库选择题目后，可带入题目和服务信息进入新建页面；入口和字段以题库实际能力为准。
- 第一版一次只选择并运行一道题。

### 3.2 选择服务

- 第一版默认且仅启用 **1110**，显示服务名称和简短说明。
- 其他服务后续按真实接入情况扩展；未接入项不可选择，不伪装为可用。
- 服务状态、权限及可运行性由后端实际能力决定；不可用时展示清楚原因。

### 3.3 准备题目

提供两个选项：

**从题库选择**

- 展示适用于当前服务的题目，并可搜索。
- 选择后展示完整题面；创建运行时携带或关联所选题目及其版本，具体字段需要先核实契约。
- 题目不适用于当前服务时不能发起，说明原因。
- 第一版已确认带入后只读：新建测评页不提供修改题库题目的入口；需要修改原题时返回题库；临时换问法时改用直接输入。不应在用户不知情时修改题库原题。
- 已创建运行必须保留当次实际题面快照或等效的可靠版本引用；题库后续编辑不应改变历史结果的题面。实现方式依现有后端能力确认。

**直接输入**

- 多行输入框支持粘贴完整问题。
- 展示当前长度与上限；1110 当前限制为最多 **500 个 JavaScript 字符单位**，前端与后端采用相同口径。
- 空题或超限时在题目附近明确提示。

### 3.4 确认与发起

- 提交前展示完整题目和服务，主要按钮为「开始测评」。
- 点击后显示「正在创建」，避免连续点击；不能把前端按钮禁用视为完整的服务端幂等保障。
- 取得运行 ID 后进入任务详情，并保存恢复所需信息。
- 明确提交失败时保留输入和可公开的错误提示。
- 连接中断且尚未取得运行 ID 时，提示“创建结果暂时无法确认”；不能静默自动重新提交。是否支持按请求标识查找及幂等，开发前应核对后端。

## 4. 运行记录

### 4.1 页面目标

支持在大量运行中快速查找和回看，一行代表一次运行。首屏优先展示真实记录和「新建测评」操作，不堆叠虚构统计卡片。

### 4.2 列表内容

| 字段 | 第一版展示 |
| --- | --- |
| 题目 | 题面摘要，完整内容进入详情查看 |
| 服务 | 例如 1110 |
| 来源 | 题库或直接输入；以接口实际可提供的数据为准 |
| 运行状态 | 运行中、已结束、失败等，以后端契约为准 |
| 评分状态 | 评分中、已完成或部分失败等摘要，不能遮盖单模型状态 |
| 开始时间 | 真实开始时间 |
| 操作 | 查看详情 |

- 默认时间倒序；题目过长时支持进入详情查看全文。
- 分页展示，不一次加载所有运行的完整回答和评分正文。
- 运行状态和评分状态各自表达；运行结束不等于题目要求已完成。

### 4.3 搜索和筛选

建议第一版支持：

- 题面关键词搜索。
- 运行状态筛选：全部、运行中、已结束、失败。
- 时间范围：今天、近 7 天、自定义区间。
- 服务筛选：第一版为 1110，后续随实际接入扩展。

筛选范围必须与实际接口一致。若接口只能搜索当前页，应明确说明或补后端能力，不能表述为搜索了全部历史。自动刷新策略、分页大小和时间语义由接口与使用体验共同确定。

### 4.4 页面状态

- **暂无记录**：显示空状态和「新建测评」。
- **筛选无结果**：显示原因并提供「清除筛选」。
- **加载失败**：展示错误和重试，不能伪装成暂无记录。
- **运行中**：以文字标明状态；可继续查看进度。
- **无权限**：解释无法访问，并给出联系管理员等可行下一步。

### 4.5 已核实的历史能力（2026-10-29）

已核对 `alpha-rsi` 管理端接口：

1. `GET /evaluations/alpha-rsi/runs` 提供分页列表（`page`、`pageSize`），返回 `total`、`running` 计数和最近批次摘要；**没有**关键词搜索、状态或时间筛选。
2. 列表条目持久化题目、来源类型、题库题号与数据集版本、开始/结束时间、耗时、运行状态、判定、机检摘要与评分摘要；回答正文不在列表索引中。
3. 单条详情用 `GET /evaluations/alpha-rsi/ask/:runId` 读取，返回题面、回答正文、`markdownSyntax`、DeepSeek 与 Qwen 的评分状态及完整解读；记录由管理端登录保护，属于团队共享，未按个人隔离。
4. 运行结束的记录会写入对象存储索引，刷新后仍可回看；运行中的记录只存在于服务进程内，服务重启后不会恢复。

因此第一版运行记录只做分页列表，不提供搜索与筛选；批量按题目发起后端尚不支持，本期只做单题。Admin 状态与持久化数据遵守项目既有 `science_admin` 数据库边界。

## 5. 任务详情

新建测评创建成功和运行记录列表均进入同一详情页面。问题与回答可以按类似对话的阅读顺序排列，但它们属于一次测评任务，不形成聊天会话。

### 5.1 基本信息

展示服务、完整题面及来源、运行状态、开始时间、结束时间或耗时，以及返回运行记录入口。题库版本或运行 ID 能获取时可提供查看，不暴露凭据。

### 5.2 问答内容

按「测试题目 → 服务回答」展示：

- 已确认采用 SSE 流式逐步展示回答。前提是登录态下可使用流式接口，不得使用公开免登录流；若登录态无流式能力，应回到评审，不静默降级为轮询。回答需服务端持久化，否则刷新后无法恢复已输出内容，该能力须在接入前核实。
- 正文支持 Markdown 阅读和复制；长内容自然展开或提供可操作的展开入口，不用固定高度隐藏内容。
- 异常或无回答时明确说明；不把不完整结果伪装成完整回答。

### 5.3 测评结果

依次展示：

1. **Markdown 机检**：状态和具体问题，说明其仅覆盖已有检查规则。
2. **任务完成情况**：模型提取的要求、各项完成状态和依据。
3. **DeepSeek**：独立状态、可理解度评分及说明。
4. **Qwen**：独立状态、可理解度评分及说明。
5. **科学检查与局限**：指出的疑点及未独立验证的内容。

每个模型独立展示「评分中、已完成、无评分、未配置、评分失败」等真实状态；一个失败不遮盖另一个结果，缺失不显示为零分。评分与运行结果分开。

用户可见的数值评分已确认统一为百分制。现有 1110 可理解度为 1–5 分，按 `原分 ÷ 5 × 100` 换算（如 `4 / 5 → 80 / 100`），换算方法须写入接口契约，并保留原始分值、量程和转换方式。百分制只表示展示量程，不是预测准确率。

### 5.4 科学可信度边界

- 运行协议通过不等于业务任务完成。
- 模型可理解度或任务完成判断不等于科学准确率。
- 文献、标准、数据、附件或仿真未进行独立核验时，不得显示为已验证正确。
- 评分可能受回答截断影响，应按接口实际标记展示，不能隐瞒。

## 6. 接口、认证和恢复：开发前核对

- 当前 1110 登录版支持提交任务并按运行 ID 查询；公开 SSE 和登录版接口的访问边界不同。
- 前端已确认采用 SSE 流式展示；接入前必须确认登录态下流式接口可用且受平台登录保护，不得使用公开免登录流。若登录态无流式能力，回到评审而不是静默降级。
- 正式接入前确认：登录态、读写权限，以及团队共享记录的归属与访问控制。
- 不承诺未验证的服务端幂等、历史列表、取消或重试能力；按实际契约设计对应操作。
- 若运行 ID 已取得，刷新和断线应查询原运行；不得依靠 SSE 自动重连重新创建任务。
- 数据缺失、历史旧版本或评分服务未配置时明确展示实际状态，不补造字段或分数。

## 7. 第一版验收

1. 从题库选择或直接输入均能带入正确的单题题面及服务；题库版本和历史题面按已确认契约正确保留。
2. 空题、超长题、无权限和提交失败有明确提示；输入不无故丢失。
3. 已取得运行 ID 后刷新、断线和重新进入，查询的是原运行而不是重复提交；流式连接中断后按已持久化的回答恢复，不从头重跑。
4. 运行、回答、DeepSeek 和 Qwen 状态分别正确；一个评分失败不影响其他结果。
5. 运行记录能按已确认的真实数据来源查找历史；搜索和筛选范围清楚。
6. 任务详情能阅读完整题目和回答，机检、逐项要求、评分及未验证边界清晰。
7. 加载、空、错误、无权限和旧记录状态有对应反馈，不使用虚构业务数据。
8. 桌面与手机端可操作，符合产品界面设计规范；浏览器联调和后端接口验证分别记录。

## 8. 已确认决策与待定问题

### 8.1 已确认（2026-10-29）

| 问题 | 决策 | 对实现的要求 |
| --- | --- | --- |
| 运行记录归属 | 团队共享 | 列表默认返回团队记录；按团队做访问控制；个人视角后续再议 |
| 题库题临时修改 | 不允许，只读 | 新建页无编辑入口；换问法走直接输入 |
| 运行中输出 | SSE 流式 | 需登录态下可用，且回答落库；断线或刷新不得重新发起任务 |
| 评分数值 | 百分制 | 1–5 分按 `原分 ÷ 5 × 100` 换算，保留原值与量程 |

### 8.2 待定

- 默认首页定为运行记录后，现有「评测工作台」保留还是移除？其禁用输入框不能与新建测评并存为第二个入口。
- 「运行中」长时间不结束时的判定与出口：超时标记失败、允许取消，还是仅提示继续等待。
- 同一用户并发提交的上限与提示。
- 团队共享下是否需要「只看我的」筛选。
