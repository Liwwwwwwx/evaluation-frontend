# Science 评测 · 产品界面设计规范

版本：v0.3（待评审）

日期：2026-10-29

适用范围：独立评测平台 Web 端的登录、工作台、题库、运行记录和结果详情。

> 本文是后续设计与开发的建议基准，不代表现有页面已经全部按此实现。本轮只制定规范，不调整页面或接入业务。尺寸以 CSS px 为单位；允许根据内容和设备作合理适配。
>
> v0.3 变更：按用户反馈，输入框聚焦不显示任何标记；细化评分状态与百分制展示；放宽表格行高和完整内容查看方式，并明确实际背景上的对比度检查。

## 1. 产品气质与设计原则

参考 ChatGPT 的使用体验：简洁、安静、以内容和当前任务为中心。保留 Science 评测自己的名称和原创标识，不复制第三方 Logo。

1. **先工作，再装饰**：首屏优先呈现当前任务、状态和下一步操作；不使用无实际作用的数据卡片或装饰图。
2. **内容优先**：长回答、题目、评分证据和错误信息应容易阅读、复制和回看；重要信息不能只靠颜色区分。
3. **一个页面一个主要动作**：同一视图只突出一个主按钮；其他操作使用次级按钮或文字入口。
4. **真实状态**：没有接入的功能显示“待接入”，没有数据时显示空状态；不使用示例数字冒充真实评测结果。
5. **结论有边界**：协议运行状态、任务完成情况、表达可理解度和科学真实性分开呈现；模型评分不等于科学真实性验证。

## 2. 布局与页面边距

### 2.1 响应式分档

| 视口宽度 | 页面形态 | 左右边距 | 导航 |
| --- | --- | --- | --- |
| ≥ 1280 | 桌面宽屏 | 主内容区 32，内容超过最大宽度后居中 | 固定侧栏 |
| 768–1279 | 桌面 / 平板横屏 | 主内容区 24 | 保留侧栏；空间不足时可收起 |
| < 768 | 手机 / 平板窄屏 | 主内容区 16；登录页 24 | 使用顶部菜单及可打开、可关闭的抽屉 |

断点是后续设计基准。当前实现以 700px 隐藏侧栏，尚无移动导航入口；要在实现对应页面时补齐，不能只隐藏导航。

### 2.2 全局框架

- 桌面侧栏宽 **256**，不随内容拉伸；侧栏内部左右留白 **12**，导航项高度 **40**。
- 顶部栏高 **64**，手机端 **56**；主要内容不被固定栏或悬浮控件遮挡。
- 登录表单最大宽 **360**；问答与长文本阅读区最大宽 **768**；题库列表和运行记录内容区最大宽 **1200**，超出后居中。
- 阅读区与输入区应共享同一中心线；表格空间不足时允许容器横向滚动，不挤压成无法阅读的多行。
- 页面标题与第一块内容间距 **32**；同一内容块之间通常 **24**；相关文本之间通常 **8**。
- 登录页主体可垂直居中，但在矮屏、输入法弹出或文字放大时应允许自然滚动，不能截断按钮或错误提示。

### 2.3 间距体系

以 4 为基础，优先使用以下离散值；除像素级边框外，不随意新增尺寸。

| 标记 | 数值 | 典型用途 |
| --- | ---: | --- |
| 1 | 4 | 图标与紧邻提示、紧凑标签内部 |
| 2 | 8 | 标签与输入框、图标与文字、段落内小间隔 |
| 3 | 12 | 控件内水平留白、列表次级间隔 |
| 4 | 16 | 常规表单项间距、移动端页面边距 |
| 5 | 20 | 同一组内相邻内容；仅在 16 / 24 不合适时使用 |
| 6 | 24 | 内容块之间、桌面页面内边距 |
| 8 | 32 | 标题到正文、较大区块之间 |
| 12 | 48 | 页面大区块之间 |
| 16 | 64 | 大屏空状态的宽松留白 |

## 3. 文字与阅读

### 3.1 字体

默认使用系统无衬线字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。代码、运行 ID 和数值可使用系统等宽字体。暂不引入外部字体资源。

### 3.2 字号与行高

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| 页面主标题 | 28 / 36 | 600 | 页面主标题、登录标题 |
| 工作台空状态标题 | 28 / 36；手机 24 / 32 | 600 | 居中欢迎语 |
| 区块标题 | 20 / 28 | 600 | 结果分区、题库分组 |
| 小标题 | 16 / 24 | 600 | 卡片标题、弹窗标题、导航栏标题 |
| 正文 / 主要输入 | 14 / 22；长回答 16 / 26 | 400 | 表单、导航、列表、Markdown 回答 |
| 辅助说明 | 13 / 20 | 400 | 字段提示、次要状态、时间 |
| 紧凑标签 | 12 / 18 | 500 | 状态标签、短说明；不用于长正文 |

- 中文正文采用正常字间距，避免大段负字距。标题按实际效果微调，不影响中文阅读。
- 数值、分数、延迟、用量一律使用等宽数字（`font-variant-numeric: tabular-nums`）；运行 ID、代码、模型标识使用等宽字体。此项为必须，不是可选，见 7.2。
- 一个页面只使用一个一级标题；长文按小标题、段落、列表自然分组。
- 长回答保留原文段落、代码块和表格；不得因固定高度隐藏内容。链接、代码和溢出表格应容易识别。
- 重要说明与错误信息使用正文或辅助说明字号，不把关键内容压成 11px 页脚。

## 4. 颜色、层次与边框

浅色主题是当前唯一主题，暂不规划深色。所有页面只引用 token，不在组件里写十六进制字面量；本轮仍不改代码，token 在后续样式统一时落地。

### 4.1 基础色

对比度为该值与 `--color-bg`（#FFFFFF）的比值。

| token | 值 | 对比度 | 用途 |
| --- | --- | ---: | --- |
| `--color-bg` | `#FFFFFF` | — | 主内容区、表格底 |
| `--color-bg-subtle` | `#F7F7F5` | — | 侧栏、轻量分组、列表隔行 |
| `--color-bg-hover` | `#ECECEA` | — | 悬停态 |
| `--color-bg-selected` | `#E4E4E1` | — | 选中态、当前导航项（比悬停深一档） |
| `--color-bg-disabled` | `#F2F2F0` | — | 禁用控件底 |
| `--color-fg` | `#202123` | 16.1:1 | 标题、正文、输入框内已输入文字 |
| `--color-fg-muted` | `#666666` | 5.7:1 | 辅助说明、时间、次要状态 |
| `--color-fg-placeholder` | `#767676` | 4.5:1 | 占位符（仍按正文标准，不得更浅） |
| `--color-fg-subtle` | `#8A8A88` | 3.5:1 | 仅图标、分隔符、禁用图形；不承载文字 |
| `--color-border` | `#E2E2E0` | — | 输入框、表格线、分割线 |
| `--color-action` | `#202321` | 16.1:1 | 主按钮底，文字用 `--color-action-fg` |
| `--color-action-hover` | `#3A3D3B` | — | 主按钮悬停 |
| `--color-action-fg` | `#FFFFFF` | — | 主按钮文字 |
| `--color-focus` | `#202123` | 16.1:1 | 按钮、链接与导航的键盘焦点标记（见 5.3） |
| `--color-overlay` | `rgba(32,33,35,.32)` | — | 弹窗遮罩 |

链接不使用独立颜色：用 `--color-fg` 加下划线，悬停时下划线加粗或加 `--color-bg-hover` 底。全站只保留一个强调色（`--color-action`），只出现在当前导航项与唯一主操作两处。

### 4.2 语义与状态色

评测的状态比普通后台多：排队、运行中、已评分、部分失败、失败、未接入。文字标签一律用 `--color-fg` / `--color-fg-muted`，状态色只用于**圆点、图标、2px 左侧标记和 8% 浅底**，避免小字号彩色文字不达标。

| token | 值 | 对比度 | 用途 |
| --- | --- | ---: | --- |
| `--color-success` | `#1A7F4B` | 5.1:1 | 已完成、通过 |
| `--color-warning` | `#8A5A00` | 5.9:1 | 未达标、需人工复核 |
| `--color-danger` | `#B42318` | 6.6:1 | 失败、错误文字 |
| `--color-info` | `#1F4E8C` | 8.3:1 | 运行中、提示 |

- 状态 = 圆点 + 文字，两者必须同时出现；「运行中」不得只用一个蓝色圆点。
- 「部分失败」使用 warning，不拆成两种颜色；「未接入」用 `--color-fg-muted`，不用 danger——配置缺失不等于执行失败。
- 图表系列色单独定义 `--chart-1..4`（`#2F5D8C`、`#B5651D`、`#3E7C69`、`#7A6E9C`），不复用状态色；每个系列必须同时有标签或不同线型，不能只靠颜色区分。

### 4.3 现有硬编码值收敛

`globals.css` 目前有 28 个十六进制字面量，统一时按此表替换，不新增中间值。

| 现值 | 收敛到 | 说明 |
| --- | --- | --- |
| `#FFFFFF` `#FAFAFA` `#F7F7F5` | `--color-bg` / `--color-bg-subtle` | `#FAFAFA` 只出现在登录输入框，属遗留，改为白底 |
| `#EDEDEB` | `--color-bg-hover` | 原 `--hover` |
| `#EAEAE8` `#E3E3E0` | `--color-bg-selected` | 导航选中、头像底 |
| `#202123` `#252525` | `--color-fg` | 正文与品牌符号 |
| `#666666` | `--color-fg-muted` | 唯一可读辅助文字色 |
| `#777777` `#888888` `#929292` `#999999` `#A0A0A0` | `--color-fg-muted` | 均承载文字，现对比度 2.9–4.5:1，全部不合规 |
| `#858585`（`--muted`） | 删除，改用 `--color-fg-muted` | 变量本身 3.7:1，不合格 |
| `#AAAAAA` `#A3A3A3` | 文字改 `--color-fg-muted`；纯图标改 `--color-fg-subtle` | 12px 以下浅灰是本轮重点整改项 |
| `#787878` | `--color-fg-subtle` | 侧栏图标 |
| `#E8E8E6` `#E1E1DF` `#DEDEDC` `#DDDDDD` `#E6E6E4` `#E5E5E5` | `--color-border` | 六种边框灰，统一成一个 |
| `#202321` / `#3A3D3B` / `#222222` | `--color-action` / `--color-action-hover` / `--color-action` | 主按钮、复选框强调 |
| `#B63838` | `--color-danger` | 登录错误文字 |

两条硬性要求：输入框中**已输入的文字**必须是 `--color-fg`（现为 `#777777`，处于 4.5:1 边缘且视觉上像占位符）；占位符需按实际背景检查对比度。`#767676` 对白底约 4.54:1，但对 `#F7F7F5` 约 4.23:1，浅灰底上应使用更深颜色。

### 4.4 圆角、阴影、层级与动效

| token | 值 | 用途 |
| --- | --- | --- |
| `--radius-xs` / `-sm` / `-md` / `-lg` / `-xl` | 4 / 8 / 10 / 16 / 24 | 标签 / 次级控件 / 输入框、卡片 / 面板 / 问答输入区 |
| `--radius-full` | 999 | 头像、圆形图标按钮 |
| `--elev-1` | `0 1px 2px rgba(16,17,19,.06)` | 下拉、浮层 |
| `--elev-2` | `0 3px 16px rgba(16,17,19,.04)` | 输入区与背景区分 |
| `--z-sticky` / `--z-sticky-col` | 10 / 11 | 粘性表头 / 粘性首列 |
| `--z-dropdown` / `--z-overlay` / `--z-modal` / `--z-toast` | 30 / 40 / 50 / 60 | 浮层层级 |
| `--motion-fast` / `--motion-base` | 120ms / 180ms | 悬停、状态切换 / 浮层进出 |
| `--ease-out` | `cubic-bezier(.2,0,0,1)` | 所有过渡 |

动效只用于状态切换和浮层进出，不做入场动画、不做缩放弹跳；`prefers-reduced-motion: reduce` 时全部置 0 毫秒。

### 4.5 使用规则

- 白色或浅色背景上的正文、辅助文字需保证可读对比度；正常文字至少 **4.5:1**，非文本图形（图标、焦点标记）至少 **3:1**。禁用态另行区别，不把低对比度文字用于关键说明。
- 不以边框包围每个区域。优先通过留白、标题和细分隔线建立层级；同一个页面不要出现大量同权重卡片。
- 状态不仅用颜色表达：如“运行中”“失败”“待评分”必须有文字；不要以灰色表示运行成功。
- 仅在需要时使用柔和阴影，例如输入区与背景需要区分时；避免厚重投影和装饰性渐变。

## 5. 控件与交互

### 5.1 输入框

- 常规输入框高 **48**，圆角 **10**，左右内边距 **14–16**；标签到输入框 **8**，同组字段之间 **16–20**。
- 文本域根据内容使用，最小高度 **96**；问答输入区圆角用 `--radius-xl`（24），并根据内容扩展或内部滚动。
- 点击或聚焦后**保持原有边框**：边框颜色、宽度、控件位置都不变，不加彩色外框、不加光晕、不加粗。这是已确认的硬约束。
- 文本输入框无论通过鼠标、触摸还是键盘聚焦，**均不显示任何额外焦点标记**：不添加竖条、轮廓、光晕、底色或其他聚焦装饰，也不改变标签或文字样式。光标及输入内容保持正常显示。
- 这项选择意味着键盘用户无法通过额外视觉提示定位尚未输入的文本输入框，属于已知无障碍限制；不能宣称已满足可见焦点要求。复选框、单选、按钮、链接和导航仍保留键盘焦点提示，见 5.3。
- 验收：分别用鼠标点击和 Tab 聚焦用户名、密码及可用的文本域，确认输入框没有新增标记，原有边框、位置和文字样式保持不变；验证输入、错误提示和提交仍正常工作。
- 标签常驻，不只依赖占位文字；错误放在相应字段附近，并说明如何修正。输入过程中不无故清除用户内容。
- 输入框、下拉框和按钮有明确的默认、禁用、错误与加载状态；禁用原因应在附近可见或通过明确提示说明。

### 5.2 按钮与图标

- 常规按钮高 **40**；表单主按钮高 **48**。圆角按钮用于主要动作；次级按钮可用浅色背景、细边框或文字。
- 桌面图标常用 **20 × 20**，图标与文本间距 **8**。纯图标按钮的可点击区域至少 **44 × 44**，同时提供可访问名称；图标自身不必放大到点击区域大小。
- 移动端主要可点击区域建议至少 **44 × 44**，避免仅将图标图形本身作为触点。
- 提交后立即显示加载状态并避免重复提交；失败时保留输入和可恢复路径。不可用功能不伪装成可点击入口。

### 5.3 导航与状态

- 侧栏选中态以浅底色和字重区分；悬停态只给轻微背景变化。图标、名称及页面标题保持一致。
- 面向键盘的导航、按钮和链接保留清晰焦点提示：`outline: 2px solid var(--color-focus); outline-offset: 2px`，不用浏览器默认样式，也不用背景色代替焦点。文本输入框按 5.1 保持无额外聚焦标记。
- 加载、空、错误、无权限和未接入状态分别给出明确文字与可执行的下一步。不要将请求失败显示为“暂无数据”。
- 涉及数据删除或不可逆操作时，按实际风险提供清楚的确认与结果反馈；本规范不预设具体业务权限或实现方式。

## 6. 页面应用

### 登录

- 保持单列、居中、最大宽 360；Logo、标题、说明、表单和反馈依次排列。
- 用户名与密码标签常驻；密码使用密码输入类型，支持浏览器密码管理；提交失败在表单中提示。
- 错误不泄漏敏感凭据或内部细节；登录中防止重复提交。真实认证与权限以服务端为准。

### 评测工作台

- 侧栏负责空间与导航，主区域集中输入题目和展示当前工作。空状态内容少而清楚，首屏可直接识别主要动作。
- 正在运行、回答输出、评分等待、失败与完成应有明确状态；长回答与评分分区分层阅读。
- 评测执行尚未接入时保持明确提示；未来接入时不将模型分数包装为科学准确率。

### 题库与运行记录

- 列表优先展示能识别题目或运行的必要字段、状态和时间；搜索、筛选与列表对齐，避免密集的卡片网格。
- 空状态区分“尚无记录”和“筛选无结果”；无权限与请求失败不得混同为空数据。
- 详情以题目、回答、机检、各模型评分、证据与局限分组；各模型缺失、失败或未配置分别表达。

## 7. 表格与评分数值

表格是本产品的主载体（题库、运行记录、模型对比），评分数值是最容易被误读的内容，两者单独规定。

### 7.1 表格

- **结构**：第一列放识别对象的字段（题目摘要或用例名），其后依次是状态、时间、数值、操作。数值列右对齐，文本列左对齐，状态列固定宽（96），内容变化不引起列抖动。
- **行高与内容**：宽松行最小高度 44，紧凑行最小高度 36，表头最小高度 40。短字段默认单行；题目摘要、错误原因和证据可按内容换行或展开，行高随内容增长。截断时须提供键盘和触屏可操作的完整内容入口，不能只依赖鼠标悬浮。
- **表头**：桌面端 `position: sticky; top: 0`，背景必须不透明（`--color-bg`），下边框 1px。对比矩阵首列同时 `sticky left: 0`，滚动时加 1px 右边框，不用阴影。
- **评分状态必须可分**：按实际接口状态展示，不能将失败、等待与缺失混为一谈。下表是现有 1110 接口的映射，其他服务需先核对各自契约：

  | 接口状态 | 展示 | 说明 |
  | --- | --- | --- |
  | `pending` | `评分中` | 尚未完成；允许继续等待或刷新 |
  | `ready` | 百分制分数及维度名称 | 成功时展示对应结果；没有合法结果时提示数据异常 |
  | `failed` | `评分失败` | 展示可公开的失败原因，不显示为零分 |
  | `absent` | `无评分` | 没有评分结果，不推断是未运行还是不适用 |
  | `unavailable` | `未配置` | 能力不可用或未启用；不当作执行失败 |

  未触发、明确不适用、已取消等其他状态仅在接口能够区分时显示对应文案；未知状态显示“状态未知”，不猜测。缺失数据不得统一显示 `—` 或作为 0 分。运行状态和各模型评分状态分开呈现。
- **排序**：默认按时间倒序；可排序列头右侧显示方向箭头，本身是按钮、可键盘操作；排序不改变筛选条件；数值列按数值排，不按字符串排。
- **横向滚动**：容器 `overflow-x: auto`，首列 sticky；表格自身可横向滚动时，页面不得同时出现横向滚动；1280 以下允许表格滚动，但主操作不能滚出视野。
- **分页**：超过 50 行分页，显示「第 x–y 条 / 共 n 条」，分页控件常显，不藏在滚动尽头。
- **行操作**：优先使用题目名称或“查看详情”链接进入详情，支持键盘和触屏；行内其他操作使用独立控件，避免嵌套交互和误触。必要时可扩展整行点击，但不得覆盖链接、按钮、文字选择或键盘操作；图标视觉 20，热区至少 44×44。
- **空状态**：区分「尚无记录」（附主要动作）与「筛选无结果」（附「清除筛选」），两者不得共用一句文案。

### 7.2 评分数值

- **格式**：用户可见的数值评分统一展示为百分制，写成 `80 / 100` 或 `80.0 / 100`，明确维度名称；百分制是展示量程，不是概率或科学准确率。非数值结果如机检状态和逐项结论不强制转换为分数。
- **换算与保真**：已有百分制分数直接展示；其他量程必须先核实评分含义和上下限，并在该评分的接口契约中明确换算方法。以现有 1110 的 1–5 可理解度为例，建议使用 `原分 ÷ 5 × 100`，`4 / 5 → 80 / 100`；这是按满分比例换算的设计提案，须在接入该服务时确认，不能把它当作接口已经返回百分制，也不能把 80 解读为科学正确率。原始分值、量程和换算方法应保留，供详情查看或审计。
- **精度与比较**：同一评分维度统一小数位，默认最多一位；必要时在详情展示更多有效位，避免不同原始值被误认为完全相同。仅在维度、规则和量程可比较时展示差值，不默认计算跨模型平均值。
- **等宽数字必用**：`font-variant-numeric: tabular-nums`；表内 14、详情 20、关键结论 28。模型名与运行 ID 用等宽字体。与 3.2 同一条要求。
- **并列而不拼接**：模型分、人工分、机检结果各自标明来源与维度；仅在满足可比条件时提供差值，单独成列并标注为百分制分差（如 `+3.2 分`），不用颜色代替正负号。
- **颜色只做辅助**：数值本身用 `--color-fg`；未达标用 `--color-warning` 的图标或 2px 左侧标记，不铺整块红底。分数颜色永远不是唯一区分手段，必须有文字或符号同时存在。
- **评分状态**与 7.1 一致：评分中、无评分、未配置和评分失败分开显示；表格与详情页使用同一套措辞，不另造同义词。
- **区间与不确定**：有置信区间时写成 `82.4（78.1–86.7）`；不为装饰画误差条，不确定度必须伴随一句来源说明。
- **禁止包装**：模型评分不得表述为「科学准确率」「正确率」，不得把多模型平均分当真值；与第 1.5 条一致，结果页文案同样受此约束。

## 8. 验收检查

每次新增或调整页面时检查：

1. 标题、正文、辅助文字和控件尺寸使用本规范的层级；主内容宽度与边距符合对应断点。
2. 320px、375px、768px、1280px 及宽屏下，无页面级意外横向滚动、截断、遮挡；表格容器的有意横向滚动除外。
3. 字体放大至 200% 时，信息、操作和错误提示仍可访问；不同长度的中文、数字和英文不会破坏布局。
4. 所有可操作控件有可辨识的名称、状态和适当的点击区域；按钮及导航可通过键盘定位，文本输入框按 5.1 验证无额外聚焦标记，并保留该选择的无障碍限制说明。
5. 使用真实、空、加载、错误、无权限和未接入等状态检查，不虚构评测数据。
6. 视觉走查至少覆盖登录、工作台以及当次新增页面；真实行为以接口与浏览器联调结果为准。
7. 焦点按 5.1 和 5.3 分别验收：文本输入框鼠标和键盘聚焦均无新增标记，其他可操作控件保留键盘焦点提示；检查 320px 与 200% 缩放。
8. token 与状态覆盖成表检查：每个文字 token 对其实际底色 ≥ 4.5:1；每个交互控件具备默认、悬停、按下、禁用、加载、错误六态（不适用项注明理由），缺项视为未完成。
